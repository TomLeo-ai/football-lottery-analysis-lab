## Verification method and boundaries

- Direct package versions were cross-checked against `apps/web/package.json`, `package-lock.json`, installed package `name`/`version`, and the Task 5 package evidence. The `tesseract.js` and `tesseract.js-core` license texts were copied byte-for-byte from the installed 7.0.0 packages.
- `tesseract.js-core` tag `v7.0.0` resolves to commit `acffef2b66eb44a31df297e11d905f4b39001068`. Its official recursive Git tree and `.gitmodules` fix the nine native submodules listed above to the recorded commits. No other native component was added to the inventory.
- The npm registry records both language packages at `1.0.0` with git head `b86746569320a6103cea84cc2b8d9ee74f0f45d3`. That commit adds the integerized `4.0.0_best_int` files and pins `tesseract-ocr/tessdata_best` at `e9f15884bc503cf905c8a1dbbc9cb14458152628`; its license text is Apache-2.0. The npm package's MIT metadata is therefore not used as a substitute for the traineddata license.
- Each native license or notice is copied without rewriting from the repository path at the exact build commit. The manifest records the local file's byte count and SHA-256 hash; the offline checker verifies both.
- This inventory concerns the packaged software and traineddata artifacts only. It does not establish ownership or clearance of upstream training corpora, glyphs, fonts, images, personal data, patents beyond the stated files, or trademarks.
